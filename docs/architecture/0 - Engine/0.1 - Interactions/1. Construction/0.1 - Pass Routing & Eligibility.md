Not every source makes it through the entire LLM wiki pipeline to massively reduce token cost analysing source material that has minimal to no real world impact on
- decisions
- architecture
- design
- team standards

### Pass Concept

Each layer and stage of the LLM wiki can be isolated into its own job, where it will only accept source material if it meets a specific threshold for that pass. Each pass is responsible for a particular stage of the ingestion lifecycle. A source's trajectory is short-circuited the moment it fails an eligibility gate — it stays at the highest pass it qualified for and waits there until a future signal (citation by a new page, weight upgrade, hub promotion) pulls it forward.

Eligibility gates per pass, in order: **boundary score → confidence weight → hub score**. Each pass has a stricter floor than the last.

---

##### **Pass 0** (Hash + Provenance Graph)
- **Overview**
	- No-LLM pass. Walks every source acquired by the connector lane, splits files into regions (tree-sitter for code, headings/blocks for docs, message-ts for chat), SHA-256s each cited region, and records the symbol/citation graph that downstream passes use to score boundaries.
- **Output/Outcome**
	- Source registry populated: one row per source with `{source_id, canonical_uri, source_class, lane, regions[]}`
	- Skip ledger seeded: `(workspace_id, source_id, region_id) → content_hash` keyed for L0
	- Provenance graph built: directed edges between symbols/files (who-calls-who, who-cites-who) — feeds Pass 1's PageRank boundary score
- **Contains**
	- [[1 - Source Page Generation, Region Content Hashing & Duplication Skip]]
	- [[1.1 - Provenance Graph]]
- **Pre-Requisites**
	- *None* — Pass 0 is the bootstrap. Only depends on the connector lane having delivered the raw bytes ([[0 - Data Connection & Acquisition]]).

##### **Pass 1** (Classifier)
- **Overview**
	- Haiku-tier model, batched. Reads each source's headline + first region and emits per-source labels: `{lane, kind_candidate, is_boundary, importance_score}`. Boundary score is PageRank over the Pass 0 provenance graph (aider's `repomap.py` algorithm). Importance is a confidence-weighted derivative of inbound-citation count + recency.
- **Output/Outcome**
	- Routing labels per source — feed L1 routing manifest as targetable vocabulary
	- Boundary set — the subset of sources that earn an L3 page in Pass 3 (typically <5% of source count)
	- Cluster seeds — sources tagged with their initial cluster id (refined in Pass 2)
- **Contains**
	- [[1.2 - Source Classifier & Clustering]]
- **Pre-Requisites**
	- Pass 0 complete for this source (provenance graph populated, hash recorded)
	- Source `confidence` ≥ classifier floor (default 0.05 — even unflagged Slack passes; below this, source halts at Pass 0)

##### **Pass 2** (Cluster Manifest)
- **Overview**
	- **Mechanical, no LLM.** Clusters Pass-1-labelled sources via Leiden over the Pass 0 provenance graph (calls/imports/cites/mentions edges), seeded by Pass 1's `domain_candidates`. Falls back to directory / channel / workspace section where graph signal is thin. Produces a structural manifest only — no prose summary (that's Pass 5).
- **Output/Outcome**
	- L2 **cluster manifest** per cluster: `{cluster_id, member_sources[], edge_set, sibling_clusters, dominant_domain, pass_1_label_summary, importance_density}`
	- Singleton-cluster flagging (clusters of size 1 merge or get `skip_summary`)
- **Contains**
	- [[2 - Cluster Summary]]
- **Pre-Requisites**
	- Pass 1 complete (sources labelled, cluster seeds assigned)
	- Provenance graph populated (Pass 0)

##### Pass 3 (Atomic Page Synthesis)
- **Overview**
	- Sonnet-tier, batched. Generates L3 atomic wiki pages for **boundary sources only** — never for leaves. Prompt template per `kind` (decision / flow / feature / interaction / sop / insight / framework) with stable head for prompt-cache hits. Each page ≤300 words, typed by frontmatter `kind`, citing region-level provenance.
- **Output/Outcome**
	- L3 pages written to `pages/*.md` with full frontmatter (`type`, `wiki`, `kind`, `sources`, `Updated`, `tags`)
	- Region back-references updated: each cited region's `cited_by[]` includes the new page id
	- Cross-link candidates flagged for Pass 4 (resolvable wikilinks + dangling slugs)
- **Contains**
	- [[3 - Atomic Page Synthesis]]
- **Pre-Requisites**
	- Pass 1 marked source as `is_boundary = true`
	- Source `confidence` ≥ Pass 3 floor (default 0.4 — Confluence-tier and above; below this, source stays in registry without a canonical page)
	- Pass 2 cluster manifest exists for the source's cluster (gives the synthesiser scope-narrowing context: sibling members + dominant domain + standards observed)

##### Pass 4 (Cross-Link Materialisation + Hub Detection)
- **Overview**
	- Opus-tier on hubs; Haiku-tier on routine resolution. Materialises the **cross-domain link graph** by converging signals from every earlier pass: Pass 0 mechanical edges (URL mentions, PR-cites-issue), Pass 1 `soft_links`, Pass 3 wikilinks. Resolves slug aliases, promotes corroborated soft links to typed edges, detects hubs (>10 inbound), detects cross-cluster bridges, surfaces contradictions, suggests "create page" candidates where convergent dangling wikilinks indicate a missing L3 page.
- **Output/Outcome**
	- L4 cross-link graph populated: edges materialised with typed `edge_kind` (cites / implements / decides_on / specifies / supersedes / contradicts / refines / quotes)
	- **Cross-domain edges** materialised: Slack-decision-page → code-page → design-doc trios resolved against the unifying L3 feature page (or flagged for creation)
	- Hub set written: pages with >10 inbound links AND/OR spanning >1 cluster
	- Dangling wikilink resolution: aliased, materialised, or promoted to "create page" suggestion
	- Contradiction queue: pages whose convergent wikilinks point at incompatible claims surface to SME review
	- L1 manifest updated: hubs promoted as canonical route targets
- **Contains**
	- [[4 - Graph Linking Materialisation]]
	- [[4.1  - Hub Detection]]
- **Pre-Requisites**
	- Pass 3 complete for all pages in the candidate hub's cluster (need page bodies + their wikilinks)
	- Page has either: ≥10 inbound wikilinks (hub gate), OR Pass 3 flagged it as contradicting an existing page, OR convergent cross-domain signals exceed threshold
	- Per-workspace Opus budget not exhausted (Pass 4 is the first pass to degrade gracefully under cost pressure — Haiku fallback for routine resolution, Opus reserved for hubs + contradictions)

##### Pass 5 (Community Summary)
- **Overview**
	- Haiku-tier, batched. Writes the prose community summary per cluster. Reads cluster manifest (Pass 2) + L3 pages (Pass 3) + Pass 4 outputs (hubs, bridges, contradictions). Produces the L2 mid-tier retrieval surface — the layer that answers global questions without dragging through every atomic page in scope. Runs **eagerly** after Pass 4 for hub clusters, **lazily at first query** for satellite clusters per [[lazy-graphrag-tradeoff]].
- **Output/Outcome**
	- L2 community summary per cluster: `{mechanism, member_inventory, hub_designation, sibling_relationships, standards_summary, open_contradictions}` — ≤500 words
	- Multi-level / super-community summaries (optional, only above ~500 pages — RAPTOR-style hierarchy)
	- Cluster index file (`<cluster_id>/index.md`) populated as the global-query entry point
- **Contains**
	- [[5 - Aggregation and Indexing Community Summary]]
- **Pre-Requisites**
	- Pass 4 complete for cluster (hubs identified, cross-cluster bridges + contradictions resolved)
	- Pass 3 produced ≥1 page in cluster, OR cluster has ≥3 non-page sources worth describing
	- Per-workspace summary budget available (eager mode); else defer to lazy resolution at query time
