### Overview
During the ingestion of source pages. It is extremely important to minimise overall compute and token usage by effectively determining which sources are important enough to convert to atomic pages. These need to be load-bearing, but every source should also extract its type (or relevance and intent to a type), associated domain to the system, importance (if boundary), patterns (this is source dependant on what is considered a pattern) 

##### Boundary Sets
- **Definition** 
	- These are the subset of sources that **should** generate their own dedicated [[3. Atomic Pages]]. This is the result of one or more pre-conditions:
		- The source sits at a meaningful structural seam
			- A meaningful Github PR
				- A Github PR that shipped a public API change, flagged a major decision or left a notable impact on the architecture
			- A top level knowledge page
				- A commonly referenced, a frequently edited, or highly accessible page (top level) that has numerous back-links and mentions
			- A load-bearing code module/function/class
				- High [[PageRank]], many imports/invocations
				- Low amount of upstream invocations (ie. We only really want top level functions at the class level instead of helper functions)
			- An ADR
			- A design document
		- The source has a notable amount of upstreams/backlinks referencing it
			- During [[6 - Linting and Drift Detection]] if the results of recent passes has resulted in the number of wiki-links surpassing a set threshold. It will generate its own synthesis page. All pages that reference this source will be adjusted to reference the page itself, given that the information that is based on the wiki-link to the source, matches the same information that is covered by the page.
- **Frequency**
	- < 5% of source pages should be marked as `Boundary Sets`
		- Tools like [[LangChain]] should be set up to determine outcome resolution
			- If it is higher. The boundary detector is too weak or is not functioning properly.
				- The PageRank threshold may be too permissive
- **Reason**
	- L3 onwards uses more capable models
		- Sonnet/Opus
	- Each call will consume a significant amount of tokens at a higher price. This helps ensure only the most relevant sources are translated into pages

##### Content Kind
- **Definition**
	- A finer-grained type than the connector's `contentType` — distinguishes *intent* within a content shape that mechanical Pass 0 cannot tell apart.
	- Examples the LLM resolves that file extension cannot:
		- `DOC_ADR` vs `DOC_README` vs `DOC_AUTOGEN_CHANGELOG` (all `.md`)
		- `CODE_PRODUCTION` vs `CODE_TEST` vs `CODE_FIXTURE` (all Kotlin/TS)
		- `SLACK_DECISION_THREAD` vs `SLACK_DEBUGGING_THREAD` vs `SLACK_BANTER`
		- `CONFIG_PRODUCTION` vs `CONFIG_EXAMPLE`
- **Detected by**
	- Hybrid: Pass 0 sets a coarse `contentType`; Pass 1 refines it via Haiku judgment when the coarse type is ambiguous.
- **Downstream consumer**
	- Pass 3 prompt template selection (different prompts per content kind)
	- L1 routing manifest scoping (`load: kind = DOC_ADR` is a common route)
	- Skip gate: certain kinds (e.g. `DOC_AUTOGEN_CHANGELOG`, `CODE_FIXTURE`) auto-set `skip_synthesis: true`

##### Page Kind Candidate
- **Definition**
	- The L3 wiki page kind this source *would* become if synthesized: one of `decision | flow | feature | interaction | sop | insight | framework | null`.
	- Drives which Pass 3 prompt template runs.
- **Detected by**
	- Haiku, using `content_kind` + first region's text + provenance signals as input.
	- Heuristic priors: ADRs → `decision`, design docs → `feature`/`flow`, code modules at high PageRank → `feature`, Slack decision threads → `decision`, runbooks → `sop`.
- **Frequency**
	- Non-null only when `is_boundary = true`. Leaves get `null` (they're not synthesized into pages).
- **Reason**
	- Lets Pass 3 dispatch to the right prompt template without re-reading the source. Avoids paying Sonnet cost to figure out "what kind of page should I write?"

##### Domain Candidates (Cluster Seeds)
- **Definition**
	- A ranked list of candidate domain labels (`["auth", "billing"]`) the source most likely belongs to. Seeds Pass 2 clustering.
- **Detected by**
	- **Lane-specific signal extractor first** (mechanical, cheap):
		- Code: path segments (`apps/auth/...` → `auth`)
		- Slack: channel name (`#auth-eng` → `auth`)
		- Notion: workspace section / parent page
		- Linear: project / label
	- **Haiku second** (for sources whose path/channel doesn't disambiguate, e.g. shared utilities, root-level docs).
- **Downstream consumer**
	- Pass 2 Leiden clustering uses these as initial assignments; refines via wikilink/symbol graph.
- **Reason**
	- Cluster quality is the bottleneck of Pass 2. Cheap mechanical signal + LLM-for-ambiguous-cases beats running clustering blind.

##### Importance Score
- **Definition**
	- Composite scalar in `[0, 1]` summarising how load-bearing the source is. Used for ordering within a boundary set, ordering of L5 drift queue, and L1 manifest priority when multiple pages match a route.
- **Components (weighted sum, classifier-tunable)**
	- PageRank score from Pass 0 provenance graph (largest weight for code; smaller for docs)
	- Inbound-citation count (wikilinks + @mentions + PR/issue references)
	- Recency (newer activity → higher)
	- Lane confidence (code 1.0 weighs more than Slack 0.05)
	- Author seniority (when available — author is a senior IC / on CODEOWNERS)
- **Detected by**
	- Mechanical aggregation of Pass 0 signals; Haiku does not score importance directly.
- **Downstream consumer**
	- L5 drift queue ordering (`weight × downstream_page_count`)
	- L1 manifest hub promotion (Pass 4)
	- Retrieval rank tiebreaker

##### Contextual Confidence Override
- **Definition**
	- An optional per-source override of the connector's default `confidence` value. Lets Pass 1 promote or demote individual sources based on observed signals.
- **Detected by**
	- Haiku, using rules like:
		- Slack thread default 0.05 → bump to 0.4 if `participantCount ≥ 4` AND `hasDecisionEmoji` AND `downstreamCitations ≥ 2`
		- Notion page default 0.4 → bump to 0.6 if `editedBy` includes someone on CODEOWNERS for the referenced code area
		- Code file default 1.0 → demote to 0.6 if `quality_flags includes WIP`
- **Downstream consumer**
	- Replaces source-level `confidence` in all downstream weighting (synthesis prompt, retrieval ranking, auto-promotion gate, drift queue priority).
- **Reason**
	- Connector defaults are coarse. A single high-signal Slack thread shouldn't be ranked alongside meeting banter; an unfinished WIP code file shouldn't carry full code-confidence.

##### Standards Detected
- **Definition**
	- Single-source flags indicating which team-level patterns / standards this source exhibits. Vocabulary is workspace-configurable.
	- Examples:
		- Code: `hexagonal-architecture`, `event-sourcing`, `transactional-boundary`, `null-safety-enforced`, `error-as-data`
		- Docs: `follows-adr-template`, `cites-sources`, `has-rollback-plan`, `has-success-criteria`
		- Slack: `decision-format-followed`, `has-rfc-link`
- **Detected by**
	- Haiku with workspace-specific standards prompt + small few-shot.
- **Downstream consumer**
	- Pass 2 cluster summaries report standard-adoption rates per cluster.
	- L1 routing manifest can scope on standard (`load: pages where standards_detected ∋ hexagonal-architecture`).
	- Drift detection flags sources that *lose* a previously-detected standard (regression signal).

##### Single-Source Patterns
- **Definition**
	- Repeated shapes detectable within a single source (e.g. "every handler in this file follows command-validate-execute"). Cross-source patterns belong to Pass 2.
- **Detected by**
	- Haiku.
- **Downstream consumer**
	- Feeds Pass 2's cross-source pattern detection (Pass 2 aggregates single-source patterns into cluster-level "common pattern" findings).

##### Skip-Synthesis Auto-Filter
- **Definition**
	- Boolean. When `true`, the source is admitted to the registry but explicitly excluded from Pass 3 even if it scores as boundary.
- **Detected by**
	- Haiku judgments mechanical filter missed:
		- Autogen content that lacks `linguist-generated` markers (handwritten changelogs, snapshot dumps)
		- Stub files / boilerplate scaffolding
		- Test fixtures and golden files
		- Documentation referring to a deprecated system marked `archived` in body text
- **Reason**
	- Pass 0's mechanical filter cannot catch everything. Haiku is cheap enough to act as the second filter layer before any expensive synthesis. Mistakes here are recoverable — `/wiki-lint` can re-evaluate stale `skip_synthesis: true` decisions.

##### Quality Flags
- **Definition**
	- Set of enums indicating the source's editorial state. Influences downstream weighting and triggers SME review.
	- Values: `STALE`, `WIP`, `INCOMPLETE`, `CONTRADICTORY`, `UNVERIFIABLE`
- **Detected by**
	- Haiku looking for explicit markers (TODO, WIP, FIXME, "draft", "do not use"), missing required sections in templated docs, contradictions against existing pages in the cluster.
- **Downstream consumer**
	- Demotes `contextual_confidence`
	- Adds page to SME-review queue when source is `boundary AND CONTRADICTORY`
	- Hides source from auto-promotion to canonical page

##### Sensitivity Flags
- **Definition**
	- Set of enums marking sources containing data that must be excluded from shared retrieval or hashed before storage.
	- Values: `PII`, `CUSTOMER_DATA`, `SECRETS_LEAKED`, `INTERNAL_ONLY`, `LEGAL_PRIVILEGED`
- **Detected by**
	- Haiku with strict pattern prompt + regex-aided detection (API keys, AWS access patterns, credit cards, emails clustered with internal-only context).
- **Downstream consumer**
	- L1 routing manifest filters: `SECRETS_LEAKED` sources never reach retrieval; `PII`-flagged sources only reach within-tenant retrieval.
	- Triggers immediate engineering alert on `SECRETS_LEAKED` so the original artifact can be remediated.
- **Reason**
	- Without classifier-level sensitivity detection, the wiki amplifies whatever leaks past the connector. Cheap to detect, expensive to remediate after the fact.

##### Soft Link Candidates
- **Definition**
	- A short list of `(target_source_id_or_slug, edge_kind, confidence)` triples representing wikilinks the classifier *suspects* should exist between this source and others, but cannot confirm without graph context.
	- Examples:
		- "This PR description mentions 'replaces the auth middleware' → candidate `supersedes` edge to whatever source represents the old middleware"
		- "This Slack thread quotes `EntityResolver.kt` → candidate `quotes` edge"
- **Detected by**
	- Haiku, with strict instruction to emit candidates only — not to assert.
- **Downstream consumer**
	- Pass 4 cross-link resolution validates these candidates against the L3 wikilink graph + provenance graph and either materialises or discards them.
- **Reason**
	- Some structural links can only be inferred from natural-language context. Mechanical Pass 0 parsers miss them; full-graph LLM resolution at Pass 4 picks the best ones up but is expensive. Soft candidates here narrow Pass 4's search space.

### Output Summary Table

| Field | Detected by | Drives |
|---|---|---|
| `is_boundary` | Mechanical (PageRank) + Haiku tiebreak | Pass 3 eligibility |
| `content_kind` | Hybrid (extension + Haiku for ambiguous) | Pass 3 prompt routing, L1 scoping |
| `kind_candidate` | Haiku (boundary sources only) | Pass 3 prompt template |
| `domain_candidates` | Mechanical (path/channel) + Haiku fallback | Pass 2 clustering seed |
| `importance_score` | Mechanical aggregation | Drift queue order, retrieval rank, hub promotion |
| `contextual_confidence` | Haiku rules | All downstream weighting |
| `standards_detected` | Haiku + workspace standards | Cluster reporting, regression detection |
| `patterns_detected` | Haiku (single-source) | Pass 2 cross-source pattern detection |
| `skip_synthesis` | Haiku post-mechanical filter | Pass 3 exclusion |
| `quality_flags` | Haiku | SME-review queue, confidence demotion |
| `sensitivity_flags` | Haiku + regex | Retrieval scoping, security alerting |
| `soft_links` | Haiku candidates | Pass 4 cross-link resolution |

### Operational Invariants

1. **One label per source per classifier version.** Re-classification overwrites; prior labels retained in history for audit.
2. **Boundary set < 5% of source count** (existing invariant).
3. **Skip-synthesis acts as a hard gate** — `skip_synthesis: true` overrides `is_boundary: true`. A boundary that's also skipped is admitted to registry + queryable, but never synthesized.
4. **Sensitivity flags are append-only at this pass.** Adding `SECRETS_LEAKED` triggers alert; removing requires explicit SME action — never auto-cleared by a later re-classification.
5. **Contextual confidence can demote but rarely promotes >0.2 above default.** Big jumps (e.g. Slack 0.05 → 0.6) require explicit SME approval; Haiku alone caps the bump.
