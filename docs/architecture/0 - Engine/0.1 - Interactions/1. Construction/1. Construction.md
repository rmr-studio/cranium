The continuous construction, maintenance, rebuilding and updating of the LLM wiki occurs every time connectors sync new source material in for consumption/re-consumption.
Upon consumption of source material, each item can go through **Up to 6 passes**
- Each pass is its own job that, depending on
	- The confidence/weighting of the source
	- The relevancy of the material and the number of linking pages
	- The affect that it has on existing source material
- Will determine if the source page carries on to the next pass/job

### Pass Ordering

| Pass | Name | Model | Builds | Doc |
|---|---|---|---|---|
| 0 | Hash + Provenance Graph | none (mechanical) | L0 ledger + L0 provenance graph | [[1 - Source Page Generation, Region Content Hashing & Duplication Skip]], [[1.1 - Provenance Graph]] |
| 1 | Classifier | Haiku, batched | per-source `ClassifierLabel` | [[1.2 - Source Classifier & Clustering]] |
| 2 | Cluster Manifest | none (mechanical Leiden) | L2 cluster manifest (structural) | [[2 - Cluster Summary]] |
| 3 | Atomic Page Synthesis | Sonnet, batched | L3 atomic pages | [[3 - Atomic Page Synthesis]] |
| 4 | Cross-Link Materialisation + Hub Detection | Opus, interactive | L4 cross-link graph + hub set + cross-domain edges | [[4 - Graph Linking Materialisation]], [[4.1  - Hub Detection]] |
| 5 | Community Summary | Haiku, eager OR lazy | L2 prose summary (per cluster, multi-level optional) | [[5 - Aggregation and Indexing Community Summary]] |

Pass 5 runs **after** Pass 4 because the community summary needs hubs, cross-cluster bridges, and contradictions — all Pass 4 outputs. Pass 2 stays mechanical (no LLM) and produces only the structural cluster manifest that Pass 3 consumes for scope context. The LLM-driven prose summary is deferred to Pass 5, where it can be eager or lazy per [[lazy-graphrag-tradeoff]].

L5 (linting + drift) is **not a pass** — it's the steady-state loop that runs after enrollment completes. See [[6 - Linting and Drift Detection]].
